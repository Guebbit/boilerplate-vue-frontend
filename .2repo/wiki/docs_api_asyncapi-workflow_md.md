# docs/api/asyncapi-workflow.md

## Purpose

Documents the AsyncAPI (SSE/event-driven) contract workflow for this frontend repo: where the spec lives, how TypeScript types are generated from it, how the "shared half" of a two-repo contract is kept in sync with the backend, and the naming/generation conventions that tie the realtime SSE client stack to the contract.

## Key elements

- **`asyncapi.yaml`** (repo root) — SSE-only contract; a verbatim copy of the backend's `asyncapi.public.yaml`. Declares one server (`sseLocal`, HTTP) and channels `observability.metrics.snapshot`, `observability.metrics.updated`, `observability.heartbeat`. Never hand-edited; synced from the backend.
- **`src/types/asyncapi.generated.ts`** — generated by `npm run gen:asyncapi`. Exports `SseEventName`, `SseEventPayload`, `MetricsSnapshotEvent`, `REALTIME_SSE_EVENT_NAMES`, and `SseEventPayloadMap`. Overwritten on every generation run; never hand-edited.
- **`scripts/generate-asyncapi-types.ts`** — runs `@asyncapi/modelina` against `asyncapi.yaml`, then appends channel constants and the SSE payload map. Byte-identical to the backend's copy of the same script.
- **`scripts/spec-identity.ts`** — tracks `asyncapi.yaml` and the generator script in a `SHARED_FILES` list so `check:spec-identity` (run from the backend) fails if this repo forks either.
- **`@types` re-export** (`src/types/index.ts`) — re-exports the generated file alongside `src/types/realtime.ts` (app-local shapes like `RealtimeMetricsEntry`, `RealtimeConnectionStatus`).
- **npm scripts** — `lint:asyncapi` (validate), `gen:asyncapi` (regenerate), `check:asyncapi-types` (assert committed types match current spec).

## Relationships

- **`asyncapi.yaml`** — the spec this page describes; the single input to the generator.
- **`package.json`** — defines `lint:asyncapi`, `gen:asyncapi`, `check:asyncapi-types` scripts and the `@asyncapi/cli` / `@asyncapi/modelina` devDependencies.
- **`src/infrastructure/create-sse-client.ts`** — consumes `REALTIME_SSE_EVENT_NAMES` and the generated payload types to build the SSE client.
- **`src/modules/realtime/store.ts`** — the `realtimeObservability` store dispatches on the generated event names/payloads.
- **`src/modules/realtime/use-realtime-observability.ts`** — composable layer over the store; reads typed state derived from the contract.
- **`src/modules/realtime/views/RealtimePlayground.vue`** — UI used to validate contract changes before broader integration.
- **`src/modules/realtime/routes.ts`** — wires SSE routes to the store; event names come from the generated constants.
- **`docs/api/endpoints.md`** — documents the REST (OpenAPI) half; this page is the async counterpart.
- **`docs/api/observability.md`** — describes the observability domain whose SSE channels are the only ones in this spec.
- **`github/workflows/ci.yml`** — runs `lint:asyncapi` and `check:asyncapi-types` in CI.
- **`README.md` / `docs/getting-started.md` / `docs/index.md`** — point developers to this page for the async contract workflow.
- **`docs/tools/runtime.md` / `docs/tools/security.md`** — contextual tooling/security docs; the SSE server declaration (`VITE_API_SSE`) is the env surface they reference.

## Notes

- **Never edit `asyncapi.yaml` here.** It is an output of the backend's `sync:frontend` step. A local edit will be silently reverted and the diff will look like a backend regression.
- **Never hand-edit `asyncapi.generated.ts`.** It is overwritten every `gen:asyncapi` run.
- The generated types are **not** in `SHARED_FILES`; the frontend and backend outputs legitimately differ (backend carries `EmailJobPayload`, `PdfJobPayload`, `WORKER_CHANNELS`). Cross-repo comparison of the *outputs* is intentionally skipped.
- Channel naming is dot-separated topic style (`observability.metrics.snapshot`). The generator derives `REALTIME_SSE_EVENT_NAMES` and `SseEventPayloadMap` from these — the single source of truth for SSE event names. Do not hardcode event-name strings elsewhere.
- The backend's full `asyncapi.yaml` includes RabbitMQ worker channels (`worker.email.send`, `worker.pdf.generate`) that are absent here by design; a browser cannot publish to or consume from a broker.
