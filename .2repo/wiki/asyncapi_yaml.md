# asyncapi.yaml

## Purpose

Auto-generated AsyncAPI 2.6.0 specification that defines the real-time (SSE) event contracts for the backend's observability stream. It exists as a single bundled output of `npm run contracts:bundle`, merging the root asyncapi contract with the observability module's contract into one machine- and human-readable document.

## Key elements

- **`channels.observability.metrics.snapshot`** — One-shot SSE event delivered immediately on connect; gives a dashboard a populated first render without waiting for the first 5-second tick.
- **`channels.observability.metrics.updated`** — Periodic SSE push (every 5 s) carrying the same payload shape as the snapshot; keeps dashboards current.
- **`channels.observability.heartbeat`** — 15-second keep-alive with no metric data; prevents idle-proxy disconnection and lets clients distinguish "alive, no change" from "stream died".
- **`components.messages.*`** — Three message definitions (`MetricsSnapshotEvent`, `MetricsUpdatedEvent`, `HeartbeatEvent`), each pointing to the shared payload schema.
- **`components.schemas.ObservabilityMetricsPayload`** — The single payload object: `timestamp`, `uptimeSeconds`, `memory` (rss/heapUsed/heapTotal/external in bytes), `http` (totalRequests/totalErrors), `realtime` (sseClients). All sub-objects use `additionalProperties: false`.
- **`servers.sseLocal`** — Declares the local SSE endpoint at `localhost:3000` over HTTP.

## Relationships

- **`openapi.yaml`** — The REST counterpart. The snapshot/updated channel descriptions explicitly reference `GET /observability/health` (defined there) and state that memory values are in the same BYTES units, so a dashboard can compare both sources without unit conversion.
- **`docs/api/asyncapi-workflow.md`** — Documents the surrounding workflow (authoring, bundling, consuming) for this contract.
- **`shared/contracts/asyncapi.root.yaml`** and **`src/modules/observability/asyncapi.yaml`** — The two source files that `npm run contracts:bundle` merges to produce this file. Edits belong in those sources, not here.

## Notes

- **Do not edit by hand.** The first line states it is generated by `npm run contracts:bundle`; all changes must go through the two source files listed in the header comment.
- **Three distinct channels, one payload schema.** Snapshot and updated carry identical shape (`ObservabilityMetricsPayload`); heartbeat reuses the same schema reference even though it carries "no metrics" in practice — the contract does not narrow its payload. Clients should rely on the channel/`messageId` to route, not on payload contents.
- **Units are bytes, not MB/GB.** The `memory` fields are integers in bytes, matching the REST health endpoint.
- **Tag `implemented`** is applied to all channels; it is the only tag defined, so any future channel lacking it would signal unimplemented status.
