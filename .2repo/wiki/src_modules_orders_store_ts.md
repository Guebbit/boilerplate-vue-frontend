# src/modules/orders/store.ts

## Purpose

Pinia store (`useOrdersStore`) providing CRUD, paginated search, and order-specific actions (cancel, hard delete, invoice download) for the `Order` entity. The CRUD and search scaffolding is generated by `useStructureCrudApi` from `@guebbit/vue-toolkit`; `cancelOrder` and `downloadInvoice` are hand-written because they don't fit the toolkit's record-shaped primitives.

## Key elements

- **`useOrdersStore`** — the store (Pinia setup store, name `'orders'`). Returns all cached state, pagination state, CRUD actions, and the two custom actions.
- **`orders` / `ordersList`** — record dictionary and flat list maintained by the toolkit's record cache.
- **`filters`, `loading`, `pageCurrent`, `pageSize`, `pageTotal`, `pageItemList`** — server-paginated search state. `pageTotal` comes from `useServerPageTotal` (captured from the API's `meta.totalPages`), not the toolkit's local counter.
- **`fetchOrders` / `fetchPaginationOrders` / `watchSearchOrders` / `fetchOrder` / `watchOrder`** — list, page, reactive-search, single-record fetch/watch generated by the toolkit.
- **`createOrder` / `updateOrder` / `deleteOrder`** — standard CRUD (create, update, soft-delete via `deletedAt`).
- **`hardDeleteOrder(orderId)`** — irreversible permanent delete; intentionally a separate method from `deleteOrder` so the destructive path can't be reached by a mis-passed flag.
- **`cancelOrder(orderId, refund?)`** — cancels an order; rethrows 409 on status race; upserts the returned record into the cache. `refund` is an operator override (ignored for customer-originated cancels, which always refund).
- **`downloadInvoice(orderId)`** — returns the invoice PDF as a `Blob` (routed through `fetchAny` since a Blob isn't a record).
- **`OrdersFilters`** — `Omit<SearchOrdersRequest, 'page' | 'pageSize'>`; the filter shape passed into the search callback.
- **`maxRecords: 5000`** — per-store cache ceiling (vs. toolkit default 100 000). On overflow the entire dictionary is dropped and repopulated with the current batch.

## Relationships

- **`@guebbit/vue-toolkit`** — `useStructureCrudApi` supplies the record cache, pagination state, and CRUD action factories. `useCoreStore` supplies shared `getLoading`/`setLoading` flags.
- **`@/ui/composables/use-server-page-total`** — provides `pageTotal` + `captureTotal`, replacing the toolkit's local-only page total with the server-reported total.
- **`@api`** — all HTTP calls (`listOrders`, `searchOrders`, `getOrderById`, `createOrder`, `updateOrderById`, `deleteOrderById`, `hardDeleteOrderById`, `cancelOrderById`, `getOrderInvoice`).
- **`@types`** — `Order`, `CreateOrderRequest`, `UpdateOrderByIdRequest`, `SearchOrdersRequest` shapes.

## Notes

- **Checkout is not in this store.** `POST /cart/checkout` is owned by `useCartStore`; this store learns about a new order the same way it learns about any other — by fetching.
- **Two `pageTotal` values exist.** The toolkit emits a local-only count (shadowed as `_localOnlyPageTotal`); the real one is the `useServerPageTotal` instance captured from `meta.totalPages` in the search response. Only the latter is returned to consumers.
- **`maxRecords` is a backstop, not a TTL-based cache.** Nothing is evicted for staleness; the bound triggers a full dictionary reset. Safe here because all lists are server-paginated; would be visible on an infinite-scroll UI.
- **`cancelOrder` upserts via `addOrder(response.data)`.** The returned record replaces the cached one so the UI re-renders the new status immediately.
- **`hardDeleteOrder` vs `deleteOrder`** — deliberately two methods rather than a boolean flag, to make the irreversible action impossible to invoke accidentally.
