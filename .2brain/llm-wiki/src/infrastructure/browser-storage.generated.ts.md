# src/infrastructure/browser-storage.generated.ts

## Purpose

Machine-generated registry of every cookie, `localStorage`, and `sessionStorage` key the app uses. It exists so that downstream code and UI (e.g. a cookie-consent table) can iterate a single typed source of truth without hard-coding storage keys. Generated from YAML contracts; the YAML files are the source of truth.

## Key elements

- **`BROWSER_STORAGE_DATA`** – `as const` array of 22 descriptor objects. Each entry carries `id`, `name` (the actual storage key), `setter` (`backend` | `frontend` | `library`), `kind` (`cookie` | `localStorage` | `sessionStorage`), `necessity` (`necessary` | `consent`), and an optional `when` gate (`analytics`, `faro`). Ordered for display.
- **`BROWSER_STORAGE_NAMES`** – `as const` record mapping each `id` → its storage `name`. Provides O(1) name lookup by id without scanning the array.

## Relationships

- **`src/infrastructure/browser-storage.ts`** – Imports both exports to read/write the actual browser storage (cookies, `localStorage`, `sessionStorage`) at runtime. The generated file supplies the *what*; `browser-storage.ts` implements the *how*.

## Notes

- **Do not edit this file.** Regenerate via `npm run regenerate` after modifying `shared/rules/browser-storage.yaml` or `contracts/cookies.yaml`.
- `BROWSER_STORAGE_NAMES` is a flat `id → name` map; it intentionally omits the other descriptor fields (`setter`, `kind`, `necessity`, `when`). Use `BROWSER_STORAGE_DATA` when you need those.
- Entries with a `when` field (`analyticsConsent`, `umamiDisabled`, `faroNavigation`) are conditionally active; consumers must respect the gate before reading/writing.
- `checkoutDraft`'s `name` ends with a colon (`checkout-draft:`), indicating it is a key prefix rather than a literal key.
