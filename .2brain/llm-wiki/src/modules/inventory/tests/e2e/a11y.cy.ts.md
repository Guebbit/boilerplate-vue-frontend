# src/modules/inventory/tests/e2e/a11y.cy.ts

## Purpose

Co-located accessibility (a11y) route registration for the inventory module. It declares *which* routes to audit and delegates the actual sweeping to a shared utility. Co-location is intentional: deleting the module removes its a11y coverage atomically, and `tests/cross-cutting/a11y-coverage.spec.ts` guards that no routed module loses its entry.

## Key elements

- **`PHONE`** — `readonly [390, 844]`; iPhone 14-class portrait width, matching `DataTable.vue`'s `mobile-breakpoint` where `StockBoard` and the 7-column `MovementLedger` stack into cards.
- **`sweepA11y('inventory', routes, 'admin')`** — single call that registers two route entries for the sweep:
  - `['inventory ledger', '/en/inventory']` — default (desktop) viewport.
  - `{ name: 'inventory ledger, phone viewport', route: '/en/inventory', viewport: PHONE }` — same route re-tested at the phone breakpoint.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — provides the `sweepA11y` function. This file is purely a declarative route list; all audit logic (axe-runner setup, assertions, reporting) lives in that support module.

## Notes

- The route array mixes two shapes: a plain `[name, route]` tuple and an object `{ name, route, viewport }`. Tooling consuming the list must handle both.
- The `PHONE` constant is local to this file, not shared—each module is expected to define (or skip) its own breakpoint constant if its mobile layout differs.
- The third argument (`'admin'`) scopes the sweep to admin-level permissions; routes requiring other roles would need a separate `sweepA11y` call.
