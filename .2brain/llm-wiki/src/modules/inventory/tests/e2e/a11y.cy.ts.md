# src/modules/inventory/tests/e2e/a11y.cy.ts

## Purpose

Co-located Cypress e2e test that runs an accessibility sweep against every route the inventory module serves (including phone-viewport variants). It is deliberately placed inside the module so that deleting the module removes its a11y coverage with it, preventing a stale central route list from pointing at removed pages.

## Key elements

- **`PHONE`** — `readonly [390, 844]` viewport constant representing an iPhone 14-class portrait; used to trigger the `mobile-breakpoint` stacking in `DataTable.vue`.
- **`sweepA11y(...)` call** — Registers the inventory module's route list with the shared sweep runner. Accepts:
  - Module name: `'inventory'`
  - Route array: plain `[name, route]` tuples and object form `{ name, route, viewport }` for viewport-specific passes (inventory ledger, preorders board products tab, preorders board orders tab, each with and without the phone viewport).
  - Auth role: `'admin'`.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` function imported here. This file supplies only the module-specific route list; all sweep logic (axe-core execution, assertions, viewport handling) lives in the support file. A cross-cutting spec (`tests/cross-cutting/a11y-coverage.spec.ts`) asserts that every routed module has a co-located file like this one.

## Notes

- The file is intentionally a *route list*, not a test suite. If you need to understand what assertions are made, read `a11y-sweep.ts`, not this file.
- Routes with a `viewport` key run the same URL at phone width; routes without it run at the default (desktop) width. Both variants are listed explicitly—there is no implicit "test every route at every breakpoint."
- Adding a new inventory-owned route requires adding it to this array; the cross-cutting coverage spec will fail if a module goes missing entirely, but it will not fail if a route is simply absent from the list.
