# src/modules/api-keys/tests/e2e/a11y.cy.ts

## Purpose

Cypress a11y sweep for the api-keys module. It registers a set of routes and states with the shared `sweepA11y` helper so that automated accessibility audits run against each variant (empty list, populated list, phone viewport, create form, error state) as the `admin` role — the only preset role with `apikeys.*` permissions.

## Key elements

- **`PHONE`** — `[390, 844]` viewport constant matching iPhone 14-class portrait; below `DataTable.vue`'s `mobile-breakpoint` where rows stack into cards.
- **`apiKeysListWithRow()`** — Mints a credential via `cy.mintApiKey()` then navigates to `/en/api-keys`, producing the "list with an existing row" state the bare route never reaches.
- **`sweepA11y('api-keys', …, 'admin')`** — The single top-level call that registers five sweep entries:
  - `list, empty` — bare `/en/api-keys` route.
  - `list, with a credential` — populated list via `apiKeysListWithRow`.
  - `list, phone viewport` — same populated list at `PHONE` size (tests the stacked-card layout).
  - `create` — `/en/api-keys/create`.
  - `create, submitted empty` — submits the form with no input; asserts `.v-messages__message` is visible (validates `aria-describedby` / announcement, not just colour).

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` helper that orchestrates the accessibility audit across the supplied route list and viewport options. This file is a pure consumer; all sweeping logic lives in that support module.
- **`tests/cross-cutting/a11y-coverage.spec.ts`** (referenced in the file docblock) — A cross-cutting spec that asserts every routed module ships one of these co-located a11y files, preventing silent loss of coverage when a module is deleted.

## Notes

- There is **no detail or edit page** in this module: a credential's fields are fixed at mint time, so the only non-trivial list state is "has at least one row."
- The file is intentionally **co-located** with the module (`src/modules/api-keys/tests/e2e/`) so that deleting the module also removes its a11y coverage, and the cross-cutting spec catches any orphan.
- The "create, submitted empty" sweep is the one entry with a `prepare` step — it clicks submit *before* the a11y scan, ensuring the error-message DOM (and its `aria-describedby` wiring) is present at scan time.
