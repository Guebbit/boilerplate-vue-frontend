# src/modules/payments/tests/e2e/a11y.cy.ts

## Purpose

Declares the list of payments-page routes that the shared a11y sweep must audit. It is co-located inside the payments module so that removing the module also removes its accessibility coverage. The file contains no test logic of its own; it is purely a route/configuration manifest passed to `sweepA11y`.

## Key elements

- **`PHONE`** — A `readonly [390, 844]` viewport tuple (iPhone 14-class portrait) used below the `DataTable.vue` mobile-breakpoint threshold.
- **`sweepA11y('payments', routes, 'admin')`** — Single call that registers six audit targets:
  - `/en/sales/payments` (all payments, desktop)
  - Same route at the `PHONE` viewport
  - `?tab=refunds`
  - `?tab=attention`
  - `?tab=awaiting`
  - Drawer-open state: clicks the first `[data-test=payment-row]` and asserts `[data-test=payment-drawer]` is visible before the sweep runs.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` helper. This file is its consumer; all navigation, viewport setup, and accessibility assertion logic lives in the sweep module. The only import in this file is `sweepA11y` from that path.

## Notes

- The `prepare` callback (drawer-open case) performs a real UI interaction (`click` on the first payment row) before the sweep executes. Ensure the payments table renders at least one row in the `admin` fixture, or the step will fail.
- Route names are free-form strings used for reporting; they are not tied to any router config.
- The third argument to `sweepA11y` (`'admin'`) sets the authenticated role for the entire sweep.
