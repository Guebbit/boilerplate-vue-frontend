# src/modules/payments/tests/e2e/a11y.cy.ts

## Purpose

Declares the accessibility (a11y) sweep routes for the payments module's staff-facing page, its tab variants, and the payment drawer. It is co-located inside the module so that deleting the module automatically removes this a11y coverage.

## Key elements

- **`sweepA11y('payments', routes, 'admin')`** — Single top-level call that registers five audit targets:
  - `payments, all` — `/en/sales/payments`
  - `payments, refunds` — `?tab=refunds`
  - `payments, needs attention` — `?tab=attention`
  - `payments, awaiting transfer` — `?tab=awaiting`
  - `payments, drawer open` — same base route, but with a `prepare` callback that clicks the first `[data-test=payment-row]` and asserts `[data-test=payment-drawer]` is visible before the sweep runs.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` function imported here. This file is purely a route-list declaration; all sweep mechanics (navigation, axe-core execution, reporting) live in that support module.

## Notes

- The route list mixes two shapes: plain `[name, route]` tuples and an object `{ name, route, prepare }` for targets that need an interaction before audit. The drawer entry is the only one using the object form.
- Selectors rely on `data-test` attributes (`payment-row`, `payment-drawer`); if those are renamed in the UI, this test breaks before the a11y check even starts.
- All routes are prefixed with `/en/` and scoped to the `admin` role (third argument to `sweepA11y`).
