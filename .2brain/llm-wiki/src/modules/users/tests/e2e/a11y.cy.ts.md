# src/modules/users/tests/e2e/a11y.cy.ts

## Purpose

Cypress E2E accessibility test for the users module. It delegates to the shared `sweepA11y` helper, passing a list of pages and dialogs that the admin must be able to access, and runs the sweep signed in as the admin role.

## Key elements

- **`userDetail()`** — Cypress command that resolves the detail-page URL (`/en/users/:id`) of the seeded non-admin account at runtime.
- **`userEdit()`** — Same pattern for the edit-page URL (`/en/users/:id/edit`).
- **`sweepA11y('users', routes, 'admin')`** — The single test call. The route array covers: users list, user create, user detail, user edit, the *manage access* dialog, and the *pause checkout* dialog. The two dialog entries use a `prepare` callback to open the dialog and assert it is visible before the a11y scan runs.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` helper. This file is the module-specific caller; the helper performs the actual page navigation, axe-core scan, and assertion logic. The helper expects a module name, a route list (static strings, resolvers, or objects with `name`/`route`/`prepare`), and a role string.

## Notes

- **Co-location is intentional.** The module docblock explains that a central route list would go stale when a module is deleted. `tests/cross-cutting/a11y-coverage.spec.ts` asserts every routed module ships one of these files, so the pattern cannot silently drop a domain.
- **Subject is the seeded non-admin, not the admin.** The `cy.loginAs('user')` account is targeted because the sweep runs *as* the admin; viewing your own row hides the controls that act on another user.
- **Dialog `name` fields are WCAG 4.1.2 accessible names** (the dialog title), not test IDs. They must match what axe-core reports as the dialog's accessible name.
- **`userDetail` / `userEdit` are functions, not strings**, so the account id is resolved at test time rather than hardcoded.
