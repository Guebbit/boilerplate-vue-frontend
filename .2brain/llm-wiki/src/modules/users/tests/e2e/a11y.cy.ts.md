# src/modules/users/tests/e2e/a11y.cy.ts

## Purpose
Declares the list of users-module routes to be exercised by the shared a11y sweep, and calls `sweepA11y` to run them as the admin. Co-located with the module so that deleting the module removes its a11y coverage in one step; a cross-cutting spec asserts every routed module ships one of these files, preventing silent loss of a domain.

## Key elements
- **`PHONE`** — `[390, 844]`, the iPhone 14-class viewport below which `DataTable.vue`'s `mobile-breakpoint` stacks rows into cards.
- **`userDetail()`** — resolves `/en/users/:id` for the seeded non-admin account at runtime (avoids hard-coding an id).
- **`userEdit()`** — resolves `/en/users/:id/edit` for the same account.
- **`sweepA11y('users', routes, 'admin')`** — registers five routes (list, list at phone viewport, create, detail, edit) and delegates execution to the shared helper.

## Relationships
- **`tests/support/e2e/a11y-sweep.ts`** — provides `sweepA11y`, the helper that iterates the route list, signs in as the given role, and runs the accessibility assertions. This file is a pure caller; all sweep logic lives in the helper.

## Notes
- The target account is the **seeded non-admin** (`cy.accountInRole('user')`), not the admin. The sweep *signs in* as admin so that row-level action controls (edit, delete) are visible; if the sweep targeted its own account those controls would be hidden.
- The duplicate "users list" entry at the `PHONE` viewport exists specifically to exercise the mobile card-stacking layout that the desktop-width sweep never reaches.
- `tests/cross-cutting/a11y-coverage.spec.ts` enforces that every routed module has a file like this one; the co-location pattern is structural, not optional.
