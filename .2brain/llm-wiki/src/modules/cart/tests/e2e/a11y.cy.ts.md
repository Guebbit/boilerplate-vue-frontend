# src/modules/cart/tests/e2e/a11y.cy.ts

## Purpose

Co-located accessibility (a11y) route sweep for the cart module. It declares *which* routes the cart module exposes and delegates the actual checking to a shared sweep helper. Co-location is deliberate: deleting the cart module also removes its a11y coverage, and a cross-cutting spec (`tests/cross-cutting/a11y-coverage.spec.ts`) asserts that every routed module has exactly one of these files, so a domain can't silently lose a11y testing.

## Key elements

- **`sweepA11y('cart', …, 'user')`** — Sweeps the signed-in cart route (`/en/cart`) as an authenticated user. One route, one screen.
- **`sweepA11y('cart — guest', …)`** — Sweeps the *guest* cart at the same route, twice:
  - *Empty guest cart* — just navigates to `/en/cart` with no prior state.
  - *Guest cart with a line* — a `prepare` callback seeds `localStorage['guest-cart']` with one in-stock product (qty 2), reloads the page, and asserts the `[data-test=guest-cart-item]` element appears before the sweep proceeds.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` function imported here. That file contains the generic sweep logic (axe-core run, assertion, report); this file is purely the route/state configuration for the cart domain.
- **`tests/cross-cutting/a11y-coverage.spec.ts`** (referenced in the module doc-block) — Asserts every routed module has a co-located `a11y.cy.ts`; this file is one of the artifacts it checks for.

## Notes

- The single URL `/en/cart` serves two distinct UIs (signed-in vs. guest). The guest variant is swept *twice* (empty + populated) to cover both states on the same route.
- Guest cart state is browser-local (`localStorage['guest-cart']`), not server-backed. The `prepare` callback is the only mechanism to seed it; there is no API call.
- Do not consolidate these sweeps into a central route list — the design intentionally couples a11y coverage to the module's lifetime.
