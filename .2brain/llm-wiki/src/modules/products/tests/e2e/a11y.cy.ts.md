# src/modules/products/tests/e2e/a11y.cy.ts

## Purpose

Declares the route list that drives the products module's automated accessibility (axe) sweep. It does not implement any test logic itself; it hands a structured list of routes, viewports, themes, and prep steps to the shared `sweepA11y` runner.

## Key elements

- **`PHONE`** — `[390, 844]` viewport constant matching iPhone 14-class portrait, used to audit the `DataTable.vue` mobile-breakpoint layout.
- **`productDetail()`** — Resolves the URL for a populated product's detail page by calling `cy.subjectId('product.rich')` (avoids hard-coded IDs).
- **`productEdit()`** — Same resolution for the edit page (`/en/products/:id/edit`).
- **`sweepA11y('products — public', …)`** — Four entries: list, detail, list-in-dark-theme, list-at-phone-viewport. All run under the shopper (public) role.
- **`sweepA11y('products — admin', …)`** — Five entries including the staff table, create, edit, and a "submitted empty" form state (prep steps click submit and assert `.v-messages__message` visibility). Runs under the `admin` profile.

## Relationships

- **Imports `sweepA11y` from `tests/support/e2e/a11y-sweep.ts`.** That module is the mechanism that iterates over this file's route entries and executes axe-core checks for each. The file is purely a configuration input to that runner.

## Notes

- Product IDs are never literals; `cy.subjectId('product.rich')` resolves against whichever backend the current Cypress profile started, so the sweep is environment-agnostic.
- The `product.rich` seed is chosen specifically because it populates the description, category chips, and image — fields that give axe something to report on.
- The dark-theme and phone-viewport entries exist because colour-contrast and layout stacking issues can pass on the default white/desktop sweep but fail in those contexts.
- The "submitted empty" entry uses a `prepare` hook to trigger validation before the axe run, so error-state markup (e.g. `aria-describedby` wiring) is present in the DOM.
