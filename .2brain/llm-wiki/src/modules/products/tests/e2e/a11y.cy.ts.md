# src/modules/products/tests/e2e/a11y.cy.ts

## Purpose

Defines the list of product-module routes to audit for accessibility (axe) via the shared `sweepA11y` harness. It splits routes into a **public** group (storefront) and an **admin** group (staff UI), and includes theme variants and pre-interaction states that would be missed by a plain page-load check.

## Key elements

- **`productDetail`** — resolves `/en/products/{id}` for the `product.rich` seeded subject, so the sweep always audits a populated record (description, category chips, image) regardless of which backend the profile started.
- **`productEdit`** — same idea, appending `/edit` to reach the admin edit page.
- **`sweepA11y('products — public', …)`** — three entries: the storefront grid, a single product detail page, and the grid rendered in **dark theme** (card/facet colours that pass on white may fail on dark).
- **`sweepA11y('products — admin', …)`** — five entries, including two that require a `prepare` step before the axe run:
  - *second language tab*: clicks the non-fallback translation tab so the remove-language button is present.
  - *submitted empty*: submits the create form with no input so all `.v-messages__message` error nodes are in the DOM for association/announcement checks.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — provides the `sweepA11y` function. This file only declares *what* to audit (route, name, theme, optional `prepare`); the sweep harness handles navigation, theme toggling, waiting for readiness, and invoking the axe engine.

## Notes

- Product IDs are resolved via `cy.subjectId('product.rich')` at run time, never hardcoded. The `rich` subject is deliberate: it is the only seeded product guaranteed to carry a description, category chips, and an image, which are the elements axe needs to flag (or clear).
- The dark-theme entry reuses the same `/en/products` route; only the `theme` key differs. If the harness does not support that key, the entry is silently a no-op—verify the sweep version before adding new theme entries.
- `prepare` callbacks run **before** the axe scan but **after** page load. They must leave the page in a stable, fully-rendered state (the admin entries use `.should('be.visible')` for this).
