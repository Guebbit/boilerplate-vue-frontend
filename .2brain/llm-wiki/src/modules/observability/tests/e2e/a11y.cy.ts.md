# src/modules/observability/tests/e2e/a11y.cy.ts

## Purpose
Declares the list of observability-module routes subject to the shared accessibility sweep. It exists co-located with the module so that deleting the module also removes its a11y coverage, preventing stale route references in a central list. A cross-cutting spec (`tests/cross-cutting/a11y-coverage.spec.ts`) enforces that every routed module carries one of these files.

## Key elements
- **`sweepA11y` call** — the single top-level invocation. Passes the module label `'observability'`, an array of route entries, and the auth role `'admin'`.
- **Route entries** — four items checked:
  - `['admin dashboard', '/en/admin']` — simple route check.
  - `['audit log', '/en/audit']` — the shop's own audit trail (distinct from the dashboard's platform-only Audit Log tab).
  - `{ name: 'admin dashboard, audit tab', route: '/en/admin', prepare: … }` — a tab-based entry whose `prepare` step calls `refuseALogin()` to seed an incident, clicks the "Audit Log" tab, and asserts a list row appears (needed because the table reflows into cards at phone widths).
  - `['realtime playground', '/en/playground/realtime']` — simple route check.

## Relationships
- **`tests/support/e2e/a11y-sweep.ts`** — provides the `sweepA11y` helper that iterates the route list, opens each route at every layout-matrix size, and runs the axe-core scan. This file is purely the per-module route data consumed by that helper.
- **`tests/support/e2e/steps.ts`** — provides `refuseALogin()`, used inside the `prepare` callback to create a test incident so the Audit Log tab has a row to render.

## Notes
- The file contains **no test declarations of its own** (`cy.visit`, `it`, etc.); all test scaffolding lives in `sweepA11y`. Adding a route here is equivalent to adding a test case.
- The audit-log tab entry exists because the default sweep only navigates to the route's initial state and never activates secondary tabs; without the explicit `prepare` step, that tab's content would go unchecked.
- `refuseALogin` is used purely as a data-seeding step (it triggers an incident), not as an authentication action.
