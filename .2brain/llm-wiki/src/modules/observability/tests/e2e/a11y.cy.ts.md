# src/modules/observability/tests/e2e/a11y.cy.ts

## Purpose

Co-located accessibility (a11y) sweep configuration for the observability module's routes. It defines *which* routes and viewports to check; the actual scanning logic is delegated to the shared sweep helper. It lives inside the module so that deleting the module removes its a11y coverage with it, and a cross-cutting spec asserts every routed module has one of these files.

## Key elements

- **`PHONE`** – `readonly [390, 844]`, the iPhone 14-class portrait viewport below which `DataTable.vue`'s `mobile-breakpoint` stacks rows into cards.
- **`sweepA11y('observability', [...], 'admin')`** – Registers the module's route list with the shared sweep. The list includes:
  - `/en/admin` (admin dashboard)
  - `/en/audit` (audit log — distinct route and `read:AuditLog` rule from the dashboard's platform-only audit tab)
  - A custom phone-viewport case for `/en/admin`'s **Audit Log tab** that clicks the tab, asserts a list row exists, and runs the sweep at the `PHONE` viewport
  - `/en/playground/realtime` (realtime playground)
- **`refuseALogin()`** call inside the phone-viewport case's `prepare` — creates a test incident so the platform audit table has at least one row to render.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — provides `sweepA11y`, the shared function that iterates the route list, drives the app, and runs the axe check. This file only supplies the configuration.
- **`tests/support/e2e/steps.ts`** — provides `refuseALogin`, a step helper that manufactures a login-refusal incident to seed the audit table for the phone-viewport case.

## Notes

- The phone-viewport audit-tab case exists because two things the default sweep never handles: (1) it must **click a tab** to reveal the table, and (2) it must run at a **narrow viewport** where `DataTable.vue` changes layout. Neither is covered by the plain route entries.
- The audit log (`/en/audit`) and the admin dashboard's audit tab (`/en/admin` → Audit Log tab) are intentionally separate entries with different auth rules; they are not duplicates.
- The `cy.contains('[role=tab]', …).click()` + `cy.get('[data-test=list-row]').should('exist')` sequence in `prepare` acts as both a precondition check (data present) and a layout trigger before the sweep runs.
