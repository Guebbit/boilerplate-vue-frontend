# src/modules/observability/tests/e2e/a11y.cy.ts

## Purpose

Co-located accessibility (a11y) sweep configuration for the observability module's own routes. It exists per-module so that deleting the module automatically removes its a11y coverage, and a cross-cutting spec (`tests/cross-cutting/a11y-coverage.spec.ts`) asserts every routed module has one of these files to prevent silent loss of domain coverage.

## Key elements

- **`PHONE`** – `[390, 844]` viewport tuple (iPhone 14-class portrait), below `DataTable.vue`'s mobile-breakpoint where rows stack into cards.
- **`sweepA11y('observability', routes, 'admin')`** – registers the module's a11y sweep under the `admin` role. The route list includes:
  - `/en/admin` (admin dashboard)
  - `/en/audit` (shop audit log — a distinct route and permission rule from the dashboard's audit tab)
  - A custom entry targeting `/en/admin` at the `PHONE` viewport that clicks the **Audit Log** tab and asserts list rows render in the stacked layout (a layout the default desktop sweep never exercises)
  - `/en/playground/realtime` (realtime playground)

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** – provides the `sweepA11y` function actually imported here; all sweep mechanics (page visits, axe-runner invocation, viewport handling) live in that file. This file is purely the declarative route list.

## Notes

- The phone-viewport audit-tab entry is the only case where a single route appears twice in the list (once at default width, once at `PHONE`); the `prepare` callback is what differentiates them.
- The audit tab is a `role=tab` element; the sweep's default behavior never opens non-default tabs, so the explicit click in `prepare` is required.
- Do not consolidate these route lists into a central file — the cross-cutting coverage spec depends on per-module co-location.
