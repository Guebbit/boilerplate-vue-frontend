# src/modules/orders/tests/e2e/a11y.cy.ts

## Purpose

Cypress a11y sweep for the orders module. It invokes the shared `sweepA11y` helper against the module's routes as both a signed-in user and an admin, covering desktop and phone-viewport layouts. Co-located with the module so that removing the module also removes its a11y coverage, preventing a central list from referencing dead routes.

## Key elements

- **`PHONE`** — `[390, 844]` viewport constant; the width at which `DataTable.vue`'s `mobile-breakpoint` stacks rows into cards.
- **`orderDetail()`** — Resolves the `/en/orders/:id` URL of a pending order owned by the current backend profile (via `cy.subjectId('order.otherPending')`).
- **`orderEdit()`** — Same, but appends `/edit` for the admin-only edit page.
- **`sweepA11y('orders — signed in', …)`** — Sweeps `/en/orders` (list) at desktop and phone viewports as the `user` role.
- **`sweepA11y('orders — admin', …)`** — Sweeps `/en/sales/orders` (list), the resolved order detail page, and the resolved order edit page (all at desktop and phone where applicable) as the `admin` role.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` helper that this file calls. The helper drives the actual accessibility assertions; this file only declares *which* routes and *as which role* to run them.
- **`tests/cross-cutting/a11y-coverage.spec.ts`** (referenced in the module doc) — Asserts that every routed module ships a file like this one, so the per-module split cannot silently drop a domain.

## Notes

- Routes are ordered by **role**, not by URL. The test resolves the concrete order ID at runtime from whichever backend the profile booted, so no hardcoded IDs appear here.
- Pending is the deliberately chosen order status: it keeps every action button enabled on the page. A disabled control and a missing control produce different a11y failures, so auditing the "everything is interactive" state is the meaningful case.
- The phone-viewport entries exist because the stacked card layout below `sm` is structurally different from the desktop table; the desktop sweep never exercises that DOM.
- The file is a `@module` (side-effect-only import); it exports nothing.
