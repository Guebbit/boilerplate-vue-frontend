# src/modules/orders/tests/e2e/a11y.cy.ts

## Purpose

Declares which orders-module routes must be accessibility-audited and under which role, by feeding them to the shared `sweepA11y` helper. It is co-located with the module so that deleting the module deletes its a11y coverage automatically; a cross-cutting spec asserts every routed module ships one of these files to prevent silent gaps.

## Key elements

- **`PHONE`** — `[390, 844]` viewport constant (iPhone 14-class portrait), the width below which `DataTable.vue`'s `mobile-breakpoint` stacks the 7-column ledger into cards.
- **`orderDetail()`** — Async helper returning `/en/orders/{id}` for the current backend profile's pending order (the "cancellable" one), whose pending status exposes every action button for auditing.
- **`orderEdit()`** — Same idea, appending `/edit`; this page is admin-only.
- **`sweepA11y('orders — signed in', …)`** — Audits the orders list at desktop width *and* at `PHONE` width, running as the `'user'` profile.
- **`sweepA11y('orders — admin', …)`** — Audits the detail and edit pages, running as the `'admin'` profile (both routes are restricted to admin/owner).

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` helper imported at the top. The helper handles viewport setup, Axe/audit execution, and reporting; this file only declares *which* routes, *which* viewports, and *which* role to use.

## Notes

- The pending status is deliberately chosen for the detail/edit sweeps: it is the state that renders every action button, and disabled vs. missing controls fail accessibility rules differently.
- The phone-viewport list entry exists because the stacked-card layout is structurally different from the desktop table; auditing only one width would miss layout-specific violations.
- `orderDetail`/`orderEdit` resolve the order ID at runtime via `cy.subjectId('order.ownerPending')`, so they adapt to whichever backend the test profile is pointed at.
