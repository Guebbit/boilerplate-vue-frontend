# src/modules/orders/tests/e2e/a11y.cy.ts

## Purpose

Cypress e2e test that runs accessibility (a11y) audits across the orders module's routes using the shared `sweepA11y` helper. It covers the orders list, detail, and edit pages under both a signed-in user and an admin profile, plus module-hosted dialogs (ship, hold, cancel-the-rest) that require interaction steps to become visible before auditing.

## Key elements

- **`orderDetail()`** — resolves the detail-page URL (`/en/orders/:id`) for a pending order owned by the current backend profile.
- **`orderEdit()`** — resolves the edit-page URL (`/en/orders/:id/edit`) for the same pending order.
- **`paidExpressOrder()`** — resolves the detail-page URL for the paid-express fixture order; used as the route for dialog audits.
- **`sweepA11y('orders — signed in', …)`** — audits the orders list as a regular user.
- **`sweepA11y('orders — admin', …)`** — audits the sales-orders staff list, order detail, and order edit as an admin.
- **`sweepA11y('orders — delivery dialogs', …)`** — opens the ship and hold dialogs via `prepare` callbacks, then audits each as an admin.
- **`sweepA11y('orders — cancel the rest dialog', …)`** — opens the cancel-remainder dialog on a partially-fulfilled order, then audits it as a user.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — imports and calls `sweepA11y`, the shared helper that drives the actual axe-core audit, profile switching, and route navigation.

## Notes

- **Co-location is intentional.** Deleting the orders module removes this file and its a11y coverage together; a central list would reference routes that no longer exist. The file header notes that `tests/cross-cutting/a11y-coverage.spec.ts` asserts every routed module has a co-located sweep file, so the split cannot quietly lose a domain.
- **Pending status is chosen deliberately** for detail/edit audits because it renders every action button in its enabled state — a disabled control and a missing control trigger different a11y failures.
- **Dialog routes require a `prepare` callback.** An unopened dialog is never in the DOM, so without the interaction step the audit would pass vacuously.
- **Route entries are polymorphic:** a plain string for static paths, or a zero-arg function returning a promise for routes that need a fixture ID resolved at test time.
