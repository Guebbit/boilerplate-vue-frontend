# src/modules/orders/store.ts

## Purpose

Pinia store that owns all order CRUD, paginated search, and order-specific actions (cancel, restore, override status, timeline, invoices, credit notes, CSV export). CRUD and search are generated by `useStructureCrudApi` from `@guebbit/vue-toolkit`; the remaining actions are hand-written because their endpoints don't fit the toolkit's record-shaped primitives.

## Key elements

- **`OrdersFilters`** — the UI-facing filter type (calendar-day strings, single `id`, CSV `sort`). Excludes pagination, which the toolkit owns.
- **`criteriaOf(filters)`** — maps `OrdersFilters` to the API's `SearchOrdersRequest` shape (instant ranges, id-as-array, sort tokens). Shared by both `searchOrders` and the CSV export so the download always matches the visible list.
- **`fetchTimeline(orderId)`** — background read of an order's timeline; deliberately outside `fetchAny` so it never flips shared `loading`.
- **`listCreditNotes(orderId)`** — background read of credit-note summaries; same `loading` isolation.
- **`useOrdersStore`** — the store. Exposes toolkit-generated state (`orders`, `ordersList`, `filters`, `loading`, pagination refs) and actions (`fetchOrders`, `fetchOrder`, `createOrder`, `updateOrder`, `deleteOrder`), plus hand-written:
  - **`hardDeleteOrder(orderId)`** — permanent delete, irreversible.
  - **`restoreOrder(orderId)`** — undoes a soft delete.
  - **`cancelOrder(orderId, refund?)`** — cancels; `updateTarget` syncs both the record cache and the per-item query entry.
  - **`overrideStatus(orderId, to, reason)`** — forced forward status change with audit reason.
  - `fetchInvoice`, `fetchCreditNotes`, `fetchCreditNote`, `exportOrdersCsv` (truncated in view).

## Relationships

- **`contracts/rest/index.ts`** (`@api`, `@types`) — source of every REST function and TypeScript type the store imports.
- **Views** (`OrdersList.vue`, `Order.vue`, `OrderEdit.vue`) — primary consumers of the store's state and actions.
- **Components** (`OrderTimeline.vue`, `AwaitingTransferTable.vue`) — call `fetchTimeline`, `listCreditNotes`, and other store actions for their data.
- **Tests** (`store.spec.ts` and the view/component specs) — exercise the store in isolation and through the views.

## Notes

- **Locale-scoped cache.** `dependsOn: () => [getCurrentLocale()]` keys the entire record cache on language, because each order embeds `OrderLineProduct` titles/descriptions resolved at fetch time. Switching locale reads a fresh scope; the toolkit discards the old one.
- **`maxRecords: 5000`.** Far below the toolkit's 100 k default. Orders carry embedded line items, so they are heavier; the bound is a critical-mass backstop, not a time-based eviction. Exceeding it drops the whole dictionary and repopulates from the incoming batch (invisible under server pagination).
- **Date filters are calendar days** (`YYYY-MM-DD`); `criteriaOf` converts them to inclusive instants via `startOfDayInstant`/`endOfDayInstant`.
- **`id` is scalar in the UI** but wrapped into a one-element array for the API in `criteriaOf`.
- **`cancelOrder` / `overrideStatus` use `updateTarget`, not `addOrder`.** This replaces both the dictionary entry *and* the per-item TanStack Query cache entry, so a sibling page's `watchOrder` sees the new status rather than a stale fresh copy.
- **`listCreditNotes` / `fetchTimeline` are outside `fetchAny`** to avoid toggling the store's shared `loading` ref, which would disable sibling buttons on the page.
- **Checkout is intentionally absent.** `POST /cart/checkout` belongs to `useCartStore`; this store learns of the new order by fetching, like any other.
