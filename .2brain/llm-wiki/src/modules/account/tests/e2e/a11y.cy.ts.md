# src/modules/account/tests/e2e/a11y.cy.ts

## Purpose

Declares the routes and page-states for the account module's accessibility sweep. It contains no sweep logic itself—only the route names, roles, and `prepare` steps that define *what* to audit. Co-located with the module so that removing the module removes its a11y coverage; a cross-cutting spec (`tests/cross-cutting/a11y-coverage.spec.ts`) enforces that every routed module has one of these files.

## Key elements

- **`UNISSUED_TOKEN`** — A placeholder token (`'a-token-nobody-issued'`) appended to the four confirm-page URLs. Real tokens are single-use and already spent by flow specs, so this exercises the "expired/invalid link" state the page renders.
- **`sweepA11y('account — guest', [ … ])`** — Registers 10 guest-visible states: login, signup, password reset, four confirm pages (each with `UNISSUED_TOKEN`), OAuth callback error, a dark-theme login variant, a submitted-empty login form, and the 2FA challenge page (reached via a full sign-in flow).
- **`sweepA11y('account — signed in', [ … ], 'user')`** — Registers authenticated states as the `user` role: profile page and the address-dialog-open modal state.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides `sweepA11y`, the function that iterates over the declared route list and runs the axe audit. This file only supplies the data.
- **`tests/support/e2e/scenario.ts`** — Provides `seedAccount`, used inside the 2FA `prepare` step to fetch the demo user's email and password for the real sign-in sequence.

## Notes

- The 2FA challenge state is reached by enrolling, signing out, and signing back in through the form—not by `cy.visit('/en/login/2fa')`—because the challenge lives in Pinia memory, not the URL. A cold visit bounces to `Login`.
- The OAuth success path is deliberately omitted: it redirects immediately and renders no content of its own. Only the error variant is audited.
- The `prepare` callbacks are synchronous Cypress commands; they run after the page loads and before the axe scan, so any state they create must be stable by the time the assertion fires.
