# src/modules/account/tests/e2e/a11y.cy.ts

## Purpose

Declares the list of routes and UI states in the **account** module that the shared a11y sweep should audit. It does not implement any auditing logic itself — it only names what to check and how to reach each state (via a `prepare` callback where needed). The file is co-located with the account module so that deleting the module automatically removes its a11y coverage; a central registry would drift.

## Key elements

- **`UNISSUED_TOKEN`** — a sentinel token string (`'a-token-nobody-issued'`) used in the hash fragment of confirm-page routes. Renders the form in the same state a visitor with an expired email link would see, without consuming a real one-time token.
- **`UNISSUED_EXPORT_ID`** — a syntactically valid 24-hex id (`'64b0c0ffee64b0c0ffee64b0'`) that matches no stored export, so the download page renders its idle and error states deterministically.
- **`sweepA11y('account — guest', …)`** — registers 10 guest-facing audit targets (login, signup, password-reset, four confirm pages, email-change undo, OAuth error callback, plus prepared states: dark-theme login, empty-submit validation, and a real 2FA challenge reached through a full sign-in flow).
- **`sweepA11y('account — signed in', …, 'user')`** — registers 3 authenticated targets (profile, export download idle state, export download 404 state, and the address-dialog-open modal), all run under the seeded `'user'` account.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — exports `sweepA11y`, the function that actually drives the audit (screenshot, axe-core scan, or similar). This file only supplies the route list and `prepare` callbacks.
- **`tests/support/e2e/scenario.ts`** — exports `seedAccount`, used in the 2FA-challenge `prepare` to look up the demo user's email and password for a real form-driven login.

## Notes

- **Co-location contract:** `tests/cross-cutting/a11y-coverage.spec.ts` asserts that every routed module has a file matching this pattern, so the module cannot be deleted (or a new one added) without updating its a11y coverage.
- **2FA challenge requires a real login:** The challenge state lives in the Pinia store, not the URL. A cold `cy.visit('/en/login/2fa')` bounces back to Login. The `prepare` block enrolls email 2FA, signs out, then logs back in through the form. It is gated behind `cy.skipUnlessMailbox()` because enrollment sends a verification email.
- **OAuth success is intentionally excluded:** The success path redirects immediately and renders no static content, so only the `?error=access_denied` variant is audited.
- **Export download page:** Nothing is fetched until the download button is pressed, so any well-formed id renders the idle page; the error state is reached by pressing the button with the unissued id.
