# src/modules/account/schemas.ts

## Purpose

Zod validation schemas for the account-module forms (address, login, signup, password-reset). Error messages are i18n thunks resolved at parse time, and every length bound is imported from the generated `@api/schemas` contract so a backend contract change propagates through `npm run gen:api` alone.

## Key elements

- **`addressText(max)`** (internal) – factory returning a `z.string().max(max)` schema; empty string passes (presence is the caller's rule).
- **`requiredAddressText(max, requiredKey)`** (internal) – wraps `addressText` with `.min(1)` for mandatory address fields.
- **`addressSchema`** (exported) – full `CreateAddressRequest` object: five required text fields, optional `label` and `phone`, required `country` (presence only, selected from an ISO 3166-1 dropdown).
- **`loginPasswordSchema`** (exported) – sign-in password: min/max from the login contract.
- **`signupPasswordConfirmSchema`** (exported) – signup confirm-password: min length only; equality with the first field is left to the form's `refine`.
- **`resetPasswordConfirmSchema`** (exported) – password-reset confirm: min length only; same equality-via-refine convention.

## Notes

- **Thunked error messages:** Every `error` is a `() => translate(key, params)` thunk, not a plain string. This defers translation to parse time so the current locale applies. When adding a new rule, follow the same pattern.
- **No hardcoded numbers:** All bounds come from `@api/schemas` imports. Do not inline a literal `max(100)`—import the generated constant instead.
- **Optional vs. required address fields:** `addressText` permits `""`; `requiredAddressText` does not. `label` and `phone` are optional by design; the other five fields and `country` are required.
- **Password equality is not here:** These schemas only enforce length. The "passwords match" check lives in each consuming form's `refine` step.
- **Shared constants for add & replace:** `addressSchema` uses the *create*-operation constants for both the add and replace flows because they share the same contract bounds.
