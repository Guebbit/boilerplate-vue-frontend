# src/modules/example/tests/e2e/a11y.cy.ts

## Purpose
Co-located Cypress a11y sweep for the example module. It feeds the shared `sweepA11y` helper a list of routes and optional state-preparation callbacks covering the signed-in screens (list, create, detail, edit) and one public screen, so that the module's accessibility coverage lives in the same directory and is deleted alongside the module.

## Key elements
- **`PHONE`** — `[390, 844]` viewport constant matching iPhone 14-class portrait; used to trigger `DataTable.vue`'s `mobile-breakpoint` card layout.
- **`CUSTOMER_PUBLISHED`** — Pinned ID of the customer's seeded published example (from the backend's `scenarios/examples.ts`).
- **`ADMIN_PUBLISHED`** — Pinned ID of the admin's published example, which the public route reads.
- **`sweepA11y('example', …)`** — Registers the user-role sweep: list (desktop + phone), create (including a "submitted empty" state that asserts `.v-messages__message` visibility), detail, and edit.
- **`sweepA1y('example, public', …)`** — Registers the anonymous sweep for the single public route `/en/examples/published/:id`.

## Relationships
- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` function that this file calls to register routes; all route/state logic delegates to that helper.
- **`tests/cross-cutting/a11y-coverage.spec.ts`** (referenced in the module doc-block) — Asserts that every routed module has a co-located a11y sweep file like this one, enforcing the split cannot silently drop a domain.
- **Backend `scenarios/examples.ts`** (referenced in the doc-block) — Seeds the pinned example IDs used here; no examples are created by this test.

## Notes
- Co-location is a convention: the file is expected to sit under `src/modules/example/tests/e2e/` so that deleting the module removes its a11y coverage atomically.
- The "create, submitted empty" entry uses a `prepare` callback to submit the blank form *before* the audit runs, ensuring error messages and their `aria-describedby` associations are present in the DOM when Axe scans.
- The phone-viewport entry exists solely to capture the `DataTable` card layout; the desktop list entry never exercises that code path.
- All example IDs are hard-coded to match the demo scenario's pinned seeds; do not replace them with created records.
