# src/modules/example/tests/e2e/a11y.cy.ts

## Purpose

Declares the list of routes that the shared `sweepA11y` helper must accessibility-audit for the example module. It covers the editor's signed-in screens (list, create, detail, edit) and one anonymous public screen. Co-locating the file under the module ensures that removing the module removes its a11y coverage in the same commit, and a cross-cutting spec enforces that no routed module is missing one of these files.

## Key elements

- **`EDITOR_PUBLISHED`** (`65e1a0000000000000000e01`) — pinned id of the editor's seeded published example, used for the detail and edit routes.
- **`ADMIN_PUBLISHED`** (`65e1a0000000000000000e04`) — pinned id of the admin's seeded published example, which the public-facing page reads.
- **`sweepA11y('example', …)`** — registers five editor-scenario routes (list, create, "create, submitted empty", detail, edit) under the `editor` persona. The "submitted empty" entry includes a `prepare` callback that clicks submit and asserts a validation message is visible.
- **`sweepA11y('example, public', …)`** — registers the single anonymous-public route (`/en/examples/published/:id`).

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — sole import; provides the `sweepA11y` helper that consumes the route array, persona string, and optional `prepare` callbacks to drive the actual a11y assertions.

## Notes

- The two id constants are **pinned** to the demo scenario's seed data (documented as living in `scenarios/examples.ts`). Do not generate or fetch them at runtime; if the scenario's seed changes, update these here.
- The "create, submitted empty" `prepare` callback exists specifically so the sweep audits the **validation-error state** (visible `.v-messages__message`, `aria-describedby` wiring), not just the empty form.
- This file is intentionally module-scoped: it must live under `src/modules/example/` so the co-location guarantee (delete module → delete a11y coverage) holds. A cross-cutting spec (`tests/cross-cutting/a11y-coverage.spec.ts`) asserts that every routed module has one of these files.
