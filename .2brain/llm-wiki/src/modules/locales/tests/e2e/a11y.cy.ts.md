# src/modules/locales/tests/e2e/a11y.cy.ts

## Purpose

Registers the locales module's routes (and one transient dialog state) with the shared `sweepA11y` runner so that axe-core accessibility assertions are run against each screen as part of the E2E suite. The file is purely declarative: it lists *what* to sweep, not *how* to sweep.

## Key elements

- **`sweepA11y('locales', routes, 'admin')`** — single call that registers all locales routes under the `locales` sweep group, authenticated as `admin`.
- **Route entries (static):** `languages board` (`/en/locales`), `dictionary board` (`/en/locales/dictionary`), `translation entries` (`/en/locales/it`).
- **Dialog-state entry:** `translation entries, entry dialog open` — same route as the entries page but with a `prepare` callback that clicks `[data-test=entry-create]` and waits for `[data-test=entry-form]` to be visible, exercising the modal-over-table a11y contract.
- **Dynamic-route entry:** `entity translations` — the `route` field is a function that calls `cy.subjectId('product.inStock')` to fetch a real product ID at runtime and builds `/en/locales/translations/product/${id}`.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — provides the `sweepA11y` function (the only import). This file is its consumer; all routes registered here are visited and asserted by that runner. No other files import this test file.

## Notes

- The entries page intentionally uses the `it` locale rather than `es`: `it` is seeded with exactly one entry, so the table is guaranteed populated without depending on a larger fixture's row count.
- The `entity translations` entry uses the *function* form of `A11ySweepRoute` (a callable that returns a URL) to avoid hardcoding a product ID; the ID is resolved against the running backend at test time.
- The dialog entry's `prepare` is synchronous Cypress chaining (`cy.get(...).click(); cy.get(...).should(...)`) and runs *before* the axe assertion for that entry.
