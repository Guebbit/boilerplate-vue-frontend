# src/modules/locales/tests/e2e/a11y.cy.ts

## Purpose

Declares the locales module's routes (and one dialog state) to the shared `sweepA11y` runner, which visits each and asserts against axe-core. This is the module-level hook that plugs locales into the cross-cutting accessibility sweep.

## Key elements

- **`sweepA11y('locales', routes, 'admin')`** — registers the locale routes with the shared runner; runs as the `admin` role.
- **`PHONE`** — `[390, 844]` viewport constant (iPhone 14-class portrait) matching `DataTable.vue`'s `mobile-breakpoint` where rows stack into cards.
- **Route entries** — six sweep targets:
  - Desktop: languages board, dictionary board, translation entries (`/en/locales/it`).
  - Phone viewport variants of the same three (exercises the stacked-card layout invisible at desktop width).
  - **Entry dialog open** — uses `prepare` to click `[data-test=entry-create]` and assert `[data-test=entry-form]` visibility before the axe scan.
  - **Entity translations** — dynamic route resolved at runtime via `cy.subjectId('product.inStock')`; exercises the function-form `A11ySweepRoute`.
- **Locale choice (`it`)** — `it` is seeded with exactly one entry, so the table is populated without depending on the `es` fixture's row count.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — sole import. Provides `sweepA11y`, which iterates the route list, applies each viewport/`prepare`/dynamic-route option, and runs the axe assertions. This file is purely declarative configuration consumed by that runner.

## Notes

- The `it` locale is used specifically for the entries page (not `es`) to keep the sweep's DOM deterministic with a single row.
- The entity-translations route is a **function** returning a `Promise<string>`; it resolves the product ID off the running backend rather than hardcoding a literal.
- The phone-viewport entries exist solely to catch layout-specific a11y issues (stacked cards) that the desktop sweep never renders.
