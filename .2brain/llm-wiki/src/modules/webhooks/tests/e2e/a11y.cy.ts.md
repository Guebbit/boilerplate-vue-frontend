# src/modules/webhooks/tests/e2e/a11y.cy.ts

## Purpose

Cypress a11y (accessibility) sweep route list for the webhooks module. It registers every routable page—including phone-viewport and form-error variants—through the shared `sweepA11y` helper so that an automated axe scan runs as the admin role. The file is co-located with the module so that deleting the module also deletes its a11y coverage; a cross-cutting spec (`tests/cross-cutting/a11y-coverage.spec.ts`) enforces that every routed module ships one of these files.

## Key elements

- **`PHONE`** — `[390, 844]` viewport constant matching `DataTable.vue`'s `mobile-breakpoint`, used to exercise the stacked-card layout the desktop sweep never sees.
- **`webhookDetail()`** — Calls `cy.createWebhookSubscription()` server-side and returns the detail-page URL (`/en/webhooks/subscriptions/:id`).
- **`webhookEdit()`** — Same creation step, returns the edit-page URL (`…/:id/edit`).
- **`webhookDeliveriesFiltered()`** — Returns the delivery-log URL pre-filtered by `?subscriptionId=…`, mirroring the deep-link state the "view deliveries" button in `WebhookTarget.vue` produces.
- **`sweepA11y('webhooks', routes, 'admin')`** — The single top-level call that registers all routes (plain, phone-viewport, and the "submitted empty" form-error variant) for the a11y sweep.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` helper imported at the top of this file; this file is one of its consumers, passing the module name, a route array, and the `'admin'` role.

## Notes

- Subscriptions are created via `cy.createWebhookSubscription()` rather than looked up because the webhooks module is from-scratch and has no seeded demo fixture.
- The "subscription create, submitted empty" route submits the form blank and asserts `.v-messages__message` is visible, specifically to catch missing `aria-describedby` associations and screen-reader announcements on validation errors.
- The file has **no default export**; its effect is entirely the side-effect of calling `sweepA11y` at module load time.
- Route entries are either `[name, url]` tuples or objects with `name`, `route`, optional `viewport`, and optional `prepare` (a Cypress chain run before the axe scan).
