# src/modules/webhooks/tests/e2e/a11y.cy.ts

## Purpose

Declares the accessibility sweep route list for the webhooks module, executed through the shared `sweepA11y` helper as the admin user. It is co-located inside the module's test directory so that deleting the module removes its a11y coverage automatically; `tests/cross-cutting/a11y-coverage.spec.ts` asserts every routed module has one of these files, preventing silent loss of a domain.

## Key elements

- **`webhookDetail()`** — Returns a Cypress chain that creates a subscription via `cy.createWebhookSubscription()` and resolves to its detail-page URL (`/en/webhooks/subscriptions/:id`).
- **`webhookEdit()`** — Same creation step, resolves to the edit-page URL (`/en/webhooks/subscriptions/:id/edit`).
- **`webhookDeliveriesFiltered()`** — Creates a subscription and resolves to the delivery-log URL pre-filtered via `?subscriptionId=` query parameter, mirroring the deep-link state the "view deliveries" button in `WebhookTarget.vue` produces.
- **`sweepA11y(...)` call** — Registers eight route entries (plain `[name, url]` tuples or objects with a `prepare` step) under the `'webhooks'` sweep, run as `'admin'`. Notable prepared states: the one-time secret reveal modal after form submission, and the empty-form validation-error state asserting `aria-describedby` associations.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides `sweepA11y`, the generic runner that iterates the route array, visits each URL, and executes any `prepare` callback before the a11y audit.
- **`tests/support/e2e/integrator.ts`** — Provides `sinkEndpoint`, used in the "create, secret revealed" prepare step to register a unique webhook URL that the form can submit against.

## Notes

- No seeded demo subscription exists (this is a from-scratch module), so detail/edit/delivery routes create one server-side via `cy.createWebhookSubscription()` rather than looking one up — same pattern as `cy.createProduct()`.
- The delivery-log filtered route reads `subscriptionId` from the query string; this is the mechanism that makes the filter state reachable for a11y testing (and the reason `WebhookTarget.vue` reads filters from the URL).
- The "secret revealed" route names the modal by its title text to satisfy WCAG 4.1.2; the one-time secret is generated server-side and only displayed in that moment.
- The cross-cutting spec `tests/cross-cutting/a11y-coverage.spec.ts` enforces that this file exists for the webhooks module, making the co-location contract testable.
