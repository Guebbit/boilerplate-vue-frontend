# src/modules/tasks/tests/e2e/a11y.cy.ts

## Purpose

Declares the accessibility (a11y) sweep routes for the tasks module's public and admin surfaces, delegating the actual audit to the shared `sweepA11y` helper. It exists so that the tasks module's a11y coverage lives alongside the module itself and is removed automatically if the module is deleted.

## Key elements

- **`sweepA11y('tasks — public', …)`** — Registers the public route (`/en/contact`) for the sweep.
- **`sweepA11y('tasks — admin', …, 'admin')`** — Registers two admin routes under the `admin` auth context:
  - Static route: `/en/tasks` (task list page).
  - Dynamic route (`route: () => …`): Creates a task via `POST /tasks`, locates it by subject through `POST /tasks/search`, and resolves the `/en/tasks/:id` URL. Needed because no seeded task exists and the initial POST returns no body.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — Provides the `sweepA11y` function that this file calls to register routes and execute the actual axe-core audit. All route definitions in this file are consumed by that helper at run time.

## Notes

- **Co-location is intentional.** A central route list would outlive the module and name dead routes. `tests/cross-cutting/a11y-coverage.spec.ts` asserts that every routed module has a file like this one, preventing silent coverage loss.
- **The admin task-detail route is a factory, not a string.** It must create a task and search for it because the task POST endpoint does not return the created record.
- **Auth context is per-sweep.** The public sweep runs unauthenticated; the admin sweep passes `'admin'` as the third argument to `sweepA11y`.
