# tests/unit/app/router/frontend-links.spec.ts

## Purpose

Validates that every backend-originated link (notification emails, sitemap) defined in `contracts/frontend-links.yaml` resolves to a real, non-catch-all route on the frontend router, and that each staff "summary" link with query parameters actually targets a list view that reads those parameters. A renamed or removed route fails here in CI rather than surfacing as a 404 in a reader's inbox.

## Key elements

- **`resolvesToAPage(template)`** — Replaces `{placeholder}` tokens with a literal, strips query/fragment, calls `router.resolve('/en/<path>')`, and asserts the result matched at least one route that is not a catch-all.
- **`SUMMARY_READERS`** — A hand-maintained map from each filtered staff summary key to the view file that reads the query, the source-level text that declares the query key, and the enum values the path must set. Used to verify both that the view source contains the declaration and that the URL's values still exist in the imported enum.
- **`sourceOf(file)`** — Reads a file under `src/modules/` so the summary tests can assert on the view's source text without importing it.
- **`beforeAll` (60 s timeout)** — Imports `@/app/router` once outside any single test's budget; mirrors the pattern in `router.spec.ts`.
- **Mocks** — Stubs `@/app/guards/authentications.ts` (`tryRestoreAuth`, `enforceRouteAccess`) and `@/infrastructure/observability/store.ts` (`useObservabilityStore`) because importing the router pulls those modules in at load time, but the guards themselves are not exercised by `resolve`.
- **Three tests in "backend links resolve"** — Iterate `rules.links`, `rules.staffPages`, and `rules.staticPages`, asserting each resolves to a real page.
- **Two tests in "staff summary paths open the filtered list"** — (1) Completeness guard: the set of `staffPages` keys whose URL contains `?` must exactly equal `Object.keys(SUMMARY_READERS)`, so a new row cannot skip the check. (2) Per-entry `it.each`: verifies the view source declares the query key and the URL carries a value that the enum still defines.

## Relationships

The dependency graph reports no registered neighbors for this file. At runtime it dynamically imports `@/app/router` (the object under test), reads `contracts/frontend-links.yaml` as plain text (generated by the `sync:frontend` task), imports `OrderFulfillmentStatus`, `OrderStatus`, and `ReturnStatus` from `@/types/enums.ts`, and reads several view files under `src/modules/` as source text.

## Notes

- The `{placeholder}` → `'x'` substitution in `resolvesToAPage` is intentional: parameter *values* are not the concern, only that the path shape matches a registered route.
- `SUMMARY_READERS` is a manual registry. If you add a new filtered staff page to `frontend-links.yaml`, you must also add a `SUMMARY_READERS` entry or the completeness test will fail.
- The enum-value assertions (`reader.accepts`) catch the case where a query param in the YAML still references a value that has been removed from the TS enum, which would silently open an unfiltered list.
- The 60-second `beforeAll` timeout is deliberate; the router's module graph is large and cold-import is expensive. Do not lower it without profiling.
