# tests/unit/i18n/i18n.spec.ts

## Purpose

Integration-style unit test for the i18n module's core functions (`_loadLocale`, `_updateLocale`, `_changeLanguage`, `getDefaultLocale`, `supportedLanguages`) run against a **real** `vue-i18n` instance rather than a mock. It exists to verify the actual locale-loading, merging, fallback, and DOM-sync behavior that `tests/unit/app/guards/locale-choice.spec.ts` deliberately leaves untested by mocking `@/i18n` wholesale.

## Key elements

- **`freshInstance()`** – factory that returns a throwaway `createI18n({ legacy: false, locale: 'en', fallbackLocale: 'en' })` so tests never mutate the app-wide singleton.
- **`withLoadedLanguagesRestored()`** – snapshots and restores the module-level `loadedLanguages` array around each test.
- **`describe('supportedLanguages')`** – asserts the list is exactly the JSON files present in `src/locales/` (en, it) and that a runtime `push('es')` is visible to other importers. Uses `vi.resetModules()` + dynamic `import()` to re-evaluate the module.
- **`describe('_loadLocale')`** – covers first-time load + activation, short-circuit when already loaded (sentinel key technique), unsupported-locale fallback, and graceful degradation when a dynamic import rejects (the `es` / API-only case).
- **`describe('_updateLocale')`** – covers registering an externally-fetched dictionary, overwriting without duplicating `loadedLanguages` entries, and the "caller wins over module contributor" merge order (guarded via `registerLocaleContributors`).
- **`describe('_changeLanguage')`** – verifies `<html lang>` and `<html dir>` sync, that the fallback dictionary is loaded so per-key fallback renders, and that load-before-activate ordering holds.
- **`describe('getDefaultLocale')`** – browser-language detection (truncated in source; uses `vi.stubGlobal`/`vi.stubEnv`).

## Relationships

- Imports all public and `_`-prefixed exports from **`@/i18n`** (the module under test) plus `routerLinkI18n` from **`@/i18n/router-link.ts`**.
- Reads **`@/locales/en.json`** and **`@/locales/it.json`** as expected-value fixtures.
- Pairs with **`tests/unit/app/guards/locale-choice.spec.ts`**, which mocks `@/i18n` and only asserts that `changeLanguage` is called with the right argument; this file verifies the call actually produces Italian output.

## Notes

- `es` is **intentionally absent** from `src/locales/`; it simulates a language supplied only by the API at runtime. Any test referencing `es` exercises the no-bundled-file path.
- The `_`-prefixed functions accept the `vue-i18n` instance as a parameter *by design* so tests can use a throwaway instance; the app-wide singleton is never mutated.
- The "caller wins over module" sub-describe blocks guard a specific regression: module dictionaries used to merge *after* the caller's dictionary, silently overwriting edited keys (972 of 1 119 keys live in module dicts).
- `vi.resetModules()` is called in `afterEach` for the `supportedLanguages` block to prevent cross-test contamination of module state.
- `localeDirections.ar = 'rtl'` is set and deleted inline within a single test (no global `afterEach`) because it is test-local.
