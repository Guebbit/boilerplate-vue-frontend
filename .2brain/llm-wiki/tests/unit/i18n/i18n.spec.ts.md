# tests/unit/i18n/i18n.spec.ts

## Purpose

Unit tests for the i18n locale machinery (`@/i18n`) exercised against a **real** `vue-i18n` instance rather than a mock. It verifies that locale loading, dictionary registration, language switching, HTML attribute sync, and per-key fallback all behave correctly. The complementary spec `tests/unit/app/guards/locale-choice.spec.ts` mocks `@/i18n` entirely to test the router guard in isolation; this file covers everything underneath.

## Key elements

- **`freshInstance()`** — creates a throwaway `createI18n({ legacy: false })` instance so tests never mutate the app-wide singleton.
- **`withLoadedLanguagesRestored()`** — snapshots the shared `loadedLanguages` array and returns a restore function for `afterEach`.
- **`describe('supportedLanguages')`** — asserts the list is derived from the `src/locales/` directory (en, it) and that a runtime-pushed locale (e.g. `es`) is accepted without a local file.
- **`describe('_loadLocale')`** — covers: loading an unloaded locale (import + activate), short-circuiting when already loaded (sentinel message check), falling back to default for unsupported locales, and resolving (not rejecting) when the dynamic import fails.
- **`describe('_updateLocale')`** — covers: registering a non-bundled dictionary, overwriting without duplicating the `loadedLanguages` entry, and the **merge-order contract** where the caller's dictionary wins over module-contributor keys on the same path while still inheriting keys the caller did not provide.
- **`describe('_changeLanguage')`** — covers: `<html lang>` sync, `<html dir>` sync (rtl/ltr from `localeDirections`), fallback dictionary loading (so per-key `t()` fallback works), and the no-op when the target locale *is* the fallback.
- **`describe('getDefaultLocale')`** — begins testing browser-language detection via a stubbed `navigator` (content truncated in source).

## Notes

- `vi.resetModules()` + re-`import('@/i18n')` is used to test module-level state (`supportedLanguages`) in isolation; always pair with `afterEach(() => vi.resetModules())`.
- `loadedLanguages` is **shared module state** with the app singleton. Every test that pushes to it must call the `withLoadedLanguagesRestored` cleanup or it leaks into sibling tests.
- `es.json` is deliberately **absent** from `src/locales/`; Spanish is the canonical "API-supplied at runtime" language. Tests treat it as unsupported-by-file but supported-by-list.
- The `_`-prefixed functions (`_loadLocale`, `_updateLocale`, `_changeLanguage`, `_ensureFallbackLoaded`) accept the i18n instance as a first argument specifically so tests can use a disposable instance.
- The "caller wins over module" sub-suite guards a historical regression where module dictionaries merged *after* the caller's, silently overwriting translation edits. Roughly 87 % of the app's keys live in module dictionaries, making this the dominant edit path.
