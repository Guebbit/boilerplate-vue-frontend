# tests/e2e/specs/a11y.cy.ts

## Purpose

Accessibility sweep for "shell" routes — pages that belong to no module (landing page, prose pages, error page) — plus the shared chrome (app bar, drawer, language menu, theme toggle, account and administration menus) that every page renders. Module-owned routes keep their a11y sweeps inside their own module so deleting a domain removes its coverage; this file is the residual, unowned set.

## Key elements

- **`sweepA11y('the shell', […])`** — anonymous-role sweep covering: home (`/en`), about, faq, terms, privacy, legal, a 404 (bad URL), the error route by address (`/en/error/500/…`), Italian home (`/it`), home in dark theme, phone viewport with navigation drawer open, and desktop with the language menu open.
- **`NAV_TOOLTIP_SHOWN`** (local const) — a single page-state that opens the pinned-cart tooltip via a real keyboard Tab / Shift+Tab cycle (so `:focus-visible` fires) and asserts the Vuetify overlay content is present. Reused inside the signed-in sweep.
- **`sweepA11y('the shell chrome, signed in', […], 'user')`** — runs under the `user` role: navigation tooltip shown, account menu open (desktop only), account menu open on phone.
- **`sweepA11y('the shell chrome, signed in as an admin', […], 'admin')`** — runs under the `admin` role: administration menu open (desktop only), phone drawer open with the admin section visible.
- **`sweepA11y`** (imported) — the shared sweep helper that drives viewport × axe-core auditing, report writing, and role setup.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — provides the `sweepA11y` function. This file is the sole caller in the shell scope; it passes route lists, optional `prepare` callbacks, viewport/theme constraints, and an optional role string. All axe execution, report output to `reports/a11y/`, and gate logic (`serious`/`critical` only) live in that helper.

## Notes

- **Completeness guarantee** is not in this file; `tests/cross-cutting/a11y-coverage.spec.ts` cross-references `src/app/router/index.ts` against the routes listed here and fails on any route it does not visit.
- **Gate threshold** is `serious` + `critical` only. Advisory findings (e.g. low contrast) are logged to `reports/a11y/` but do not fail the run.
- **Open-menu states** are restricted to `viewports: ['desktop']` because a Vuetify menu is positioned once against its activator; the same menu is audited open at phone size separately.
- **Tooltip visibility** check uses Vuetify's `.v-tooltip.v-overlay--active .v-overlay__content` because the overlay content has `pointer-events: none`, which Cypress reports as "covered" (invisible) even though axe and a real user see it.
- **Keyboard focus** for the tooltip relies on `cy.realPress` for Tab / Shift+Tab; `.focus()` alone does not trigger `:focus-visible`.
- The sweep runs under the **demo profile**, the same as every other spec in `ci.yml`.
