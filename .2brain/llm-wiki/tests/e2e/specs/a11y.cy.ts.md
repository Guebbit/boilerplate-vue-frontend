# tests/e2e/specs/a11y.cy.ts

## Purpose

Accessibility e2e sweep for the "shell" — routes that belong to no module (landing page, four prose pages, error page) and the shared chrome every page renders (app bar, navigation drawer, language menu, theme toggle, account/admin menus). Module-owned routes have their own sweeps under `src/modules/<name>/tests/e2e/a11y.cy.ts`; this file exists so that deleting a domain does not orphan a11y coverage, and so shared chrome is audited once rather than duplicated per module.

## Key elements

- **`PHONE`** — `[390, 844]` viewport constant; the breakpoint below which the nav bar collapses into the drawer.
- **`sweepA11y('the shell', …)`** — first sweep, unauthenticated. Covers `/en`, four prose pages, a 404, the error route by its own address (`/en/error/500/…`), `/it` (locale swap), dark theme, drawer-open on phone, and language-menu-open.
- **`NAV_TOOLTIP_SHOWN`** — state definition for the pinned-entry (cart) tooltip. Opens the tooltip via real keyboard `Tab`/`Shift+Tab` (not `.focus()`) so `:focus-visible` fires, then asserts the Vuetify overlay is active.
- **`sweepA11y('the shell chrome, signed in', …, 'user')`** — runs the tooltip state plus the account menu open, under the `user` role.
- **`sweepA11y('the shell chrome, signed in as an admin', …, 'admin')`** — runs the admin menu open and the phone drawer with all sections (including `drawer-section-admin`), under the `admin` role.

## Relationships

- **`tests/support/e2e/a11y-sweep.ts`** — provides the `sweepA11y()` helper that this file imports. That helper (per its docs) runs axe, gates on `serious`/`critical` only, and writes full reports to `reports/a11y/`.
- **`tests/cross-cutting/a11y-coverage.spec.ts`** (referenced in the file header, not a graph neighbor here) — parses the router and fails if any route is missing from this file's route list, guaranteeing completeness.

## Notes

- **Gate severity:** only `serious` and `critical` axe violations fail a run. Advisory-level findings (e.g. low-contrast color pairs) are logged and written to `reports/a11y/` but do not block CI.
- **Interaction-gated UI:** the drawer, menus, tooltip, and dark theme are not present in the initial DOM — each `prepare` callback must trigger them before axe runs. Forgetting a `prepare` means axe never sees the element.
- **Tooltip focus quirk:** the pinned-entry tooltip opens on `:focus-visible`. `cy.get(…).focus()` does not set that pseudo-class, so the test uses `cy.realPress('Tab')` then `cy.realPress(['Shift','Tab'])`. Vuetify tooltip content also carries `pointer-events: none`, which Cypress interprets as "covered" (not visible); the assertion therefore checks the `.v-tooltip.v-overlay--active` class instead.
- **Locale coverage:** `/it` is included solely to catch a translated label that lost its `aria-` counterpart — the only functional difference from `/en`.
- **Runs under the demo profile** (same as every other spec in `ci.yml`); the `user`/`admin` role argument to `sweepA11y` is what switches the signed-in state.
