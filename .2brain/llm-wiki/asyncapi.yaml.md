# asyncapi.yaml

## Purpose
Bundled AsyncAPI 3.0.0 contract that documents every real-time and event-driven channel in the boilerplate backend — SSE observability streams and outbound webhook events. It is the single generated source of truth for what the backend emits, over which transport, and with which payload, so that consumers (dashboards, subscribers, tooling) can rely on a stable schema without reading runtime code.

## Key elements
- **`asyncapi` / `id` / `info`** — Root metadata; the `info.version` (2.0.0) is independently versioned from `openapi.root.yaml` and any change is flagged as breaking by `check:asyncapi-breaking`.
- **`servers.sseLocal`** — Points to `localhost:3000` over HTTP; the endpoint that serves SSE streams (`/observability/events`).
- **`servers.subscriberEndpoint`** — A VARIABLE server (`{subscriberHost}`, `{subscriberPath}`). Not a host this app runs; it represents the per-subscription HTTPS URL that the backend opens an outbound connection to when delivering webhooks.
- **Channels (`observability.*`)** — Three SSE channels: `metrics.snapshot` (one-shot on connect), `metrics.updated` (5 s tick), `heartbeat` (15 s keep-alive). Each carries `x-transport: sse`, which `scripts/contracts/generate-asyncapi-types.ts` reads to select SSE channels for type generation.
- **Channels (`order.*`, `payment.*`, `return.*`)** — Eleven webhook channels, each bound to `subscriberEndpoint`. They carry the business-event payloads (order lifecycle, payment outcomes, return lifecycle).
- **`operations`** — One operation per channel, `action: send`, with descriptions that trace back to the emitting code path (e.g. `orders/services/crud.ts`, `payments/services/refunds.ts`).
- **`components.messages`** — Referenced via `$ref`; the actual message schemas live in the source YAML files listed in the header comment.
- **Header comment** — Identifies this file as generated by `npm run contracts:bundle` from `shared/contracts/asyncapi.root.yaml`, `src/modules/observability/asyncapi.yaml`, and `src/modules/webhooks/asyncapi.yaml`.

## Notes
- **Do not edit directly.** The top-of-file comment marks it as generated; all changes must go through the three source YAML files and then `npm run contracts:bundle`.
- **Version is a breaking-change sentinel.** `check:asyncapi-breaking` reports *any* edit to `info.version` as breaking; increment it only when you intend a deliberate break. It does not track the OpenAPI version.
- **`x-transport` is load-bearing.** The type-generation script keys off this extension, not the `observability.` name prefix. Adding a channel without it will silently exclude it from SSE type output.
- **`subscriberEndpoint` is not a deployable host.** It exists to satisfy Spectral rules (`asyncapi-servers`, `asyncapi-channel-servers`) while still allowing per-subscription URLs. Do not treat it as a configurable server in the usual sense.
- **Webhook events are derived, not standalone.** Several (e.g. `order.paid`, `order.shipped`) are filtered projections of a single `order.status_changed` domain event rather than 1 : 1 domain events; the mapping lives in `orders/events.ts`.
