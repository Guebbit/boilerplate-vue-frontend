# asyncapi.yaml

## Purpose

A **generated, read-only** AsyncAPI 3.0.0 document that serves as the single bundled contract for all real-time and event-driven flows (SSE streams and outbound webhooks) in the boilerplate. It is produced by `npm run contracts:bundle` by merging the root fragment and every module's AsyncAPI fragment into one addressable reference. Downstream tooling (type generation, Spectral lint rules, API documentation) consumes this file rather than the individual fragments.

## Key elements

- **`x-transport: sse`** – A custom extension on channel objects (e.g. `observability.metrics.snapshot`, `notifications.created`). `scripts/contracts/generate-asyncapi-types.ts` reads this field to decide which channels are SSE; it is *not* inferred from the channel name prefix.
- **`servers.subscriberEndpoint`** – A variable server (`{subscriberHost}` / `{subscriberPath}`) representing the outbound webhook destination. Every webhook channel binds to this server. It is not a host this application listens on; it exists so Spectral rules that require a server binding still pass.
- **`servers.sseLocal` / `servers.sseNotificationsLocal`** – Concrete `localhost:3000` endpoints for the observability and notification SSE streams, respectively.
- **`channels`** – One entry per event: `observability.*`, `notifications.*` (SSE) and `order.*`, `shipment.*`, `payment.*`, `return.*`, `user.*`, `example.*` (webhook). Each declares its message `$ref` and, for webhooks, the `subscriberEndpoint` server binding.
- **`operations`** – Pairs each channel with an `action` (`send`) and a description of delivery timing (e.g. snapshot-on-connect, 5-second tick, per-event push).
- **`components.messages`** – (truncated in the listing) the shared schema definitions referenced by every channel message.

## Relationships

- **`shared/contracts/asyncapi.root.yaml`** + **`src/modules/*/asyncapi*.yaml`** – Source fragments that `npm run contracts:bundle` merges to produce this file. Editing this file directly is overwritten on the next bundle.
- **`scripts/contracts/generate-asyncapi-types.ts`** – Consumes this file; specifically reads the `x-transport: sse` extension to select SSE channels for TypeScript type generation.
- **`README.md`** – Documents the project-level contract workflow (`contracts:bundle`, Spectral rules) that this file is the output of.
- **`contracts/`** – Parent directory; this file is the canonical async contract artifact inside it.

## Notes

- **Do not edit by hand.** The header comment and the `# Code generated by` marker make this explicit. All changes go through the source fragments listed in the header, then re-bundle.
- **Version is pinned to `0.1.0`** (SemVer initial development). The breaking-change check in CI intentionally ignores this field, so bumping it does not gate merges.
- **`subscriberEndpoint` is a placeholder, not a deployable URL.** It exists purely to satisfy AsyncAPI's "every channel must have a server" rule. The actual host/path is resolved per subscription at runtime.
- **SSE channel selection is extension-driven, not name-driven.** Do not rely on the `observability.` or `notifications.` prefix to identify SSE channels; the generator trusts only `x-transport`.
- **`defaultContentType` is `application/json`** for all channels; there is no per-channel override in the visible portion.
