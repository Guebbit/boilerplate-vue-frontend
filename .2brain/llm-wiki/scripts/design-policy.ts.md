# scripts/design-policy.ts

## Purpose

Central configuration module for all design-lint rules. It imports the Vuetify theme's colour maps and exports every tunable knob—severity levels, class patterns, thresholds, and colour-name derivations—that the ESLint design rules and cross-cutting design specs read. Keeping the knobs here (pure data, no side effects) means a spec can load the policy without a browser, and tuning enforcement is a single-file edit.

## Key elements

- **`DesignSeverity`** — type alias (`'error' | 'off'`) used to type per-rule severity; every rule ships at `'error'` because CI enforces `--max-warnings 0`.
- **`themeColorNames()`** — returns a `ReadonlySet<string>` of every colour name a template may reference, derived from the light theme keys, Vuetify defaults, `lighten-N`/`darken-N` steps, and `on-*` counterparts. `design-tokens.spec.ts` validates this set against Vuetify's own computation.
- **`AmbiguousUtility`** — interface describing a class name generated by both Vuetify and Tailwind with different semantics; carries a `pattern`, a `restrict` flag, and a `message`.
- **`RestrictedClass`** — interface for a refused class pattern with a `pattern` regex and a `message`; matched in order (first hit wins).
- **`DESIGN_POLICY`** — the main `as const` object bundling all knobs:
  - `arbitraryRepeatLimit`, `rootFontSize`, `colorKeywords`
  - `severity` map (all nine design checks → `'error'`)
  - `vuetifyOwnedClasses` (e.g. `elevation-N`)
  - `ambiguousUtilities` array (fraction widths, `h-screen`, `order-first/last`, `align-baseline`, `text-wrap`, `bg-black|white|transparent`)
  - `restrictedClasses` array (arbitrary `vh`, `white`/`black` colour utilities, bare `z-100+`, `hover:` visibility toggles, and the catch-all `[` arbitrary-value rule)
  - `mobileStrategy` sub-object (dialog/table tags, owner file, scroll directive)
  - `cssInvasiveness` sub-object (`localZIndexMax`, `disallowedUnits`)
  - `tailwindEntryPoint`, `colorProps`
- **`CSS_NAMED_COLORS`** — `ReadonlySet<string>` of all CSS Color Module L4 named colours, lower-cased; a string matching one of these is treated as a colour literal.
- **`HEX_COLOR`** (module-private regex) — matches 3/4/6/8-digit hex literals not embedded in a longer word, path, or entity.

## Relationships

- **`src/ui/vuetify/theme.ts`** — sole import source; provides `light`, `VARIATION_FAMILIES`, `VUETIFY_DEFAULT_COLORS`, `variations`.
- **`scripts/eslint/design-config.ts`** — reads `DESIGN_POLICY` and `themeColorNames()` to build the ESLint rule options.
- **`eslint.config.ts`** — top-level ESLint configuration that pulls in the rules assembled by `design-config.ts`; this file is a sibling of `module-manifest.ts` in that import chain.
- **`scripts/eslint/mobile-strategy.ts`** — reads `DESIGN_POLICY.mobileStrategy` to know which tags, bindings, and the owner file to enforce.
- **`scripts/eslint/theme-token.ts`** — reads `DESIGN_POLICY.colorProps`, `themeColorNames()`, and `CSS_NAMED_COLORS` to validate colour prop bindings.
- **`scripts/audit/css-invasive/scan.ts`** — reads `DESIGN_POLICY.cssInvasiveness` thresholds for the z-index / unit scan.
- **`tests/cross-cutting/design-tokens.spec.ts`** — loads `themeColorNames()` and asserts it matches Vuetify's generated set.
- **`tests/cross-cutting/utility-collisions.spec.ts`** — loads `DESIGN_POLICY.ambiguousUtilities` and verifies it against a live measurement of Vuetify vs. Tailwind output.
- **`tests/cross-cutting/design-arbitrary-values.spec.ts`** — exercises the `restrictedClasses` patterns and `arbitraryRepeatLimit` against fixture templates.

## Notes

- **First-match-wins ordering.** In `restrictedClasses`, the general `\[[^\]]*?\d…vh` and the bare `[` catch-all are listed last; a new specific rule must go *before* them or it will be swallowed.
- **`restrict: false` in `ambiguousUtilities`** means the class is *not* blocked—only annotated. Only entries with `restrict: true` generate a lint error.
- **Severity is binary by design.** The `'off'` option exists for the type but no rule currently uses it; a softer level would be invisible in CI anyway.
- **Sibling to `module-manifest.ts`.** Both are consumed by `eslint.config.ts` through `design-config.ts` in the same pattern; editing one does not affect the other's loading.
- **`String.raw`** is used for every regex in the policy to avoid accidental escape-sequence interpretation.
