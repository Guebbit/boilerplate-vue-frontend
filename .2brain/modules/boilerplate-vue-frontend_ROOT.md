# / (repository root)

## Purpose

The repository root of a contract-first Vue 3 + TypeScript SPA boilerplate. It holds the project's top-level tooling configuration, the generated API contracts (REST and AsyncAPI) that every other module codes against, Docker-based deployment definitions, and a self-contained VitePress documentation site. The app is designed to run with no backend at all; when a backend is present, all shapes are pinned to the contracts bundled here.

## Key parts

- **Generated API contracts** — `openapi.yaml` and `asyncapi.yaml` are bundled (read-only) specs. `contracts/rest/` holds the derived TypeScript types, Zod schemas, error-code catalogue, route-lookup tables, and upload MIME types. `contracts/authorization-keys.yaml` + `permission-vocabulary.ts` define the permission model. `contracts/cookies.yaml` and `contracts/frontend-links.yaml` keep backend-emitted values in sync with the frontend. All are regenerated via `npm run contracts:bundle` / `npm run gen:api`; never hand-edited.
- **Deployment & containers** — `docker-compose.yml` (dev: Vite + VitePress), `docker-compose.production.yml` (prod: static bundle on nginx), and `docker/Dockerfile{,.production,.docs}` plus `docker/docker-entrypoint.d/` scripts that inject runtime config, `security.txt`, and robots directives at container start.
- **Documentation site** — `docs/` is a VitePress project (config in `docs/.vitepress/config.mts`, custom theme in `theme/index.ts`) covering getting-started, design-system theory, and tooling guides (Docker, env vars, observability, Umami, visual regression, touch testing).
- **Project-level configuration** — `eslint.config.ts` (flat config with architectural tier and module-boundary rules), `cypress.config.ts` (e2e viewport, profiles, Node tasks), `knip.config.ts` (dead-code audit), `index.html` (DOM shell and script load order), `mutation-baseline.json` (mutation-testing reference scores).
- **Meta / onboarding** — `README.md`, `INSTALL.md`, `SECURITY.md`, `CLAUDE.md` (coding conventions, e.g. ban on `any`).

## How it connects

- **`src/` and its modules** consume the generated types in `contracts/` and the OpenAPI/AsyncAPI specs; every module's `openapi.yaml` and `authorization.yaml` fragment feeds back into the bundled files at the root.
- **`scripts/` and `scripts/audit/`** produce or validate the root-level generated artifacts (contract bundling, codegen, knip, mutation baselines, ESLint boundary checks).
- **`scripts/e2e/`** is exercised through the task registry declared in `cypress.config.ts`.
- **`docker/`** builds and serves the compiled output of `src/app/` and the VitePress site defined under `docs/`.
- **`src/ui/` and `src/ui/composables/`** are styled per the design-system rules documented in `docs/theory/design-system.md` and enforced by the ESLint design-policy rules in `eslint.config.ts`.

## Where to start

Read **`README.md`** for the one-paragraph project pitch and the two-repo mental model, then **`openapi.yaml`** (or the smaller `contracts/rest/index.ts`) to see the shape of every API surface the frontend will talk to. Together they answer "what does this app do?" and "what data crosses the wire?" before you ever open a component.

It extends `tsconfig.app.json` and narrows the included files to the scope relevant to unit and cross-cutting tests (contracts, `src`, co-located module specs, `tests/`), while explicitly excluding Cypress e2e specs so they are not type-checked under Vitest's ambient types.
- `vite.config.ts` — Vite configuration for the application's dev server, build, and plugin stack. It wires together Vue 3, Vuetify, Tailwind CSS, and custom HTML transformation, defines path aliases, controls chunk splitting, and coordinates the dev-server port with the Docker Compose setup.
- `vitest.config.mutation.ts` — Vitest configuration consumed exclusively by Stryker's Vitest runner (`npm run test:mutation`). It layers a small set of sandbox-compatibility overrides on top of the shared base config so that the dry run and mutant runs succeed inside Stryker's `.stryker-tmp/sandbox-*` copy of the project.
- `vitest.config.ts` — Vitest configuration for the unit and component test suite (jsdom-based: pure functions, stores, composables, single Vue components). It resolves and merges the app's Vite config with test-specific settings, producing a single object that downstream configs can build on.
