## Container scripts

Same three verbs per runtime. The container runs the same `dev` script, with `--host 0.0.0.0`
added by compose so the published port is actually reachable.

| Script            | Job                                                                 | Read more                                 |
| ----------------- | ------------------------------------------------------------------- | ----------------------------------------- |
| `compose:restart` | restart the compose stack                                           | [Docker & Podman](./docker-and-podman.md) |
| `compose:rebuild` | rebuild images and restart the stack                                | [Docker & Podman](./docker-and-podman.md) |
| `compose`         | any other compose subcommand, e.g. `npm run compose -- logs -f app` | [Docker & Podman](./docker-and-podman.md) |

All three expand to `${CONTAINER_ENGINE:-podman} compose`. Export `CONTAINER_ENGINE=docker` in your shell to use docker instead — a **shell** variable, not a `.env` entry, because npm does not read `.env` and never sees what is written there. Compose itself does read `.env`, which is why every other setting on this page can live in it and this one cannot. Keep the choice in step with the backend stack: the two are started side by side.

## Contract and codegen scripts

| Script                      | Job                                                                                                                                                                                       | Read more                                        |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `regenerate`                | **After every pull.** `gen:api`, `gen:asyncapi`, `gen:permission-vocabulary`, `gen:shared-rules` — the whole client rebuilt from the specs the backend handed over; `postinstall` runs it | [OpenAPI Workflow](../api/openapi-workflow.md)   |
| `gen:api`                   | Regenerate `contracts/rest.generated/` from `openapi.yaml` via orval                                                                                                                      | [OpenAPI Workflow](../api/openapi-workflow.md)   |
| `gen:asyncapi`              | Regenerate `contracts/asyncapi.generated.ts` from `asyncapi.yaml`                                                                                                                         | [AsyncAPI Workflow](../api/asyncapi-workflow.md) |
| `gen:permission-vocabulary` | Regenerate `contracts/permission-vocabulary.generated.ts` (the `PermissionAction` type) from the backend's `actions:` list                                                                | [Contracts](../reference/contracts.md)           |
| `gen:shared-rules`          | Regenerate the `*.generated.ts` files from `shared/rules/*.yaml` (and the JSON Schemas beside them)                                                                                       | [Shared rules](./shared-rules.md)                |

Generated output is gitignored: `postinstall` (`npm run regenerate`) rebuilds it on every `npm install` and `npm ci`, and the images run it after `COPY . .`. After pulling a spec change, run `npm install`. There is nothing to format or commit.

`openapi.yaml` and `asyncapi.yaml` are **owned by the backend** and arrive here through its `npm run sync:frontend`. Nothing in this repo produces them; `npm run check` fails if they drift. So the sequence across the pair is: backend `npm run regenerate` → commit → pull here → `npm run regenerate` here.

Those two, the authorization keys and the demo webhook sink's three TLS files (`scripts/e2e/tls/`) are the whole list — `SHARED_FILES` in the backend's `scripts/pairing/spec-identity.ts` is what both the copy and the gate read. The demo dataset is **not** on it: this repo keeps no copy, and the e2e suites seed from the backend's own `scenarios/` instead.

## Audit scripts

The programs an AI audit runs (`scripts/audit/*/scripts/`). The audits themselves are prompts, not
scripts: see [AI Auditing](./ai-auditing.md).

| Script                  | Job                                                                                                                                                                           | Read more                                             |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------- |
| `audit:design:capture`  | Photographs the app for the design review: runs the sweeps in capture mode, writes PNG tiles and a manifest. A live e2e; not in the gate                                      | [Design Review](./design-review.md)                   |
| `audit:design:plan`     | Splits the last design capture into batches small enough for one reviewer's context                                                                                           | [AI Auditing](./ai-auditing.md)                       |
| `audit:design:check`    | Checks that every tile and `file:line` a design review cites exists; exits 1 when one does not                                                                                | [AI Auditing](./ai-auditing.md)                       |
| `audit:css`             | Prints every invasive-CSS hit (`file:line`, check, snippet, fix); `-- --json` for a machine. The gate is `css-invasiveness.spec.ts`. Reads source only                        | [Design Lint](./design-lint.md#the-invasive-css-scan) |
| `audit:shallow`         | The `code-shape` audit's shallow-code counter (small functions, pass-throughs, lazy files), reading each SFC's script too; writes `<out>/shallow.json` (`--out <run folder>`) | [AI Auditing](./ai-auditing.md)                       |
| `audit:locale-keys`     | Lists locale keys nothing in the app reads (`file: dot.path`); report-only, exits 0                                                                                           | [AI Auditing](./ai-auditing.md)                       |
| `audit:test-candidates` | The `test-honesty` audit's first cut: an ESLint run (report only, never a gate) listing tests whose every assertion is weak; `-- -o <file> <paths>` writes the JSON           | [AI Auditing](./ai-auditing.md)                       |
| `audit:unused`          | `knip`: unused files, exports and dependencies, as candidates for `code-shape`; never a gate                                                                                  | [AI Auditing](./ai-auditing.md)                       |
| `audit:duplicates`      | `jscpd`: copy-paste clones, as candidates for `code-shape`; writes `<out>/jscpd/`                                                                                             | [AI Auditing](./ai-auditing.md)                       |
